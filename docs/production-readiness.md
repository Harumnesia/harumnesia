# Phase 9 production readiness

**Decision: NOT READY FOR PRODUCTION DEPLOYMENT.** The local production candidate passes its code, data, bundle, browser, accessibility, and security checks. The expanded Phase 9 CI workflow has not yet run on a reviewed commit. The Phase 9 rule requires green CI for the candidate itself; the successful [baseline CI run](https://github.com/Harumnesia/harumnesia/actions/runs/36841987170) covers only `d4eae0d`, before these changes. Review and commit the Phase 9 changes, then require a successful remote workflow before Phase 10 deployment. No deployment was made.

Evidence below was collected on 1 October 2026 from baseline `d4eae0dfe504a707a230b0847de8c32596a39570`, with the Phase 9 working tree. Local checks used Windows, Node `23.11.0`, pnpm `10.30.3`, and headless Chrome `138.0.7204.101`; CI remains configured for Node 22. Measurements are observations on this machine, not performance guarantees.

## Data and repository evidence

The frozen canonical SHA-256 remains `f4651860b999f5765ef31b4df968eccd1c982a7a092365d76d0846021b4f36f2`; runtime SHA-256 remains `b11cb9d69ddcbf65ff7753d34972586930eadc56150ff2f5174f0545997cdb24`. `pnpm dataset:validate` compares the generated artifacts with committed reports and verifies deterministic ID order and exact runtime projection. No data file or recommender scoring code changed.

The initial archive test exposed a Windows checkout issue: with `core.autocrlf=true`, tracked JSON became CRLF, causing hash and formatting validation to fail. The new LF attribute fixed this; a separate clean checkout then passed frozen install, validation, formatting, and build without V1 siblings or ignored files. It produced the same ten asset bytes as the source checkout. The local host used Node 23; the Node 22 workflow must still be run remotely for this candidate.

## Browser and bundle evidence

Using the final production build through Vite preview, observed cumulative worker/runtime requests were:

| Stage                              | Worker JS | Runtime JSON | Taxonomy JSON |
| ---------------------------------- | --------: | -----------: | ------------: |
| Landing                            |         0 |            0 |             0 |
| Discover before submit             |         0 |            0 |             4 |
| First Top 5                        |         1 |            1 |             4 |
| Repeated Top 5, same SPA session   |         1 |            1 |             4 |
| Result to detail, same SPA session |         1 |            1 |             4 |

Direct local and international detail pages each initialized their own worker/runtime in a new document session, as expected. Unknown routes and direct no-session results did not request runtime data. Automated frontend tests cover recoverable taxonomy, recommendation, and detail loading/error states. The four taxonomy assets are separate hashed JSON files. The runtime and worker are separate from the main bundle, and the main JavaScript gzip size remains unchanged from Phase 8.5. The CSS correction adds 52 B raw and 17 B gzip; its new content hash changes the main JS filename and `index.html` gzip by 2 B. Total emitted size is 10,167,977 B raw / 1,827,855 B gzip (inventory gzip level 9). This is build size, not one page's network transfer.

The worker retains the parsed dataset and indexed recommender inside one worker instance. Its shared initialization Promise prevents duplicate fetch/index work for concurrent calls. The client monotonically numbers requests, removes pending entries on response, and rejects/terminates on worker errors; retry creates a new worker. `createRecommender()` validates untrusted JSON with shared schemas before use. The worker sends Top 5 records or one requested detail, never the full dataset. Further worker memory instrumentation is useful in Phase 10H but no lifecycle defect was reproduced.

## Accessibility, security, and remaining work

Keyboard input in Chrome reached the skip link, activated the mobile menu, selected a `bergamot` tag with Enter, and removed it with Space. `prefers-reduced-motion: reduce` disabled button transition and smooth scrolling while loading/status text remained present. The original small ochre `#a37f1c` was below 4.5:1 against paper; Phase 9 uses `#806117` for small ochre text (5.77:1 on white, 5.49:1 on parchment, 5.21:1 on inset paper), retaining the accent ochre for decorative treatment. No layout width changed.

The repository scan found six `console` calls in offline scripts and none in browser code. Production URL construction uses build-generated same-origin asset URLs; the image manifest requires canonical local paths and provenance. The UI does not insert untrusted HTML. The public repository still contains canonical source references and dataset provenance, so a separate rights/attribution review is needed before any broader reuse claim. There is no current evidence of a critical/high security issue or a documented prohibition on technical deployment.

**Release blocker:** obtain a green remote run of the edited Phase 9 CI workflow for the reviewed candidate. Do not infer that result from the baseline run or local Windows gates. After that, Phase 10 may proceed under [deployment contract](./deployment.md); Phase 10H should add real-device and production-domain verification. This Phase 9 work stops before deployment and remains uncommitted for review.
